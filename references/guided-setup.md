# 生成网站 + 引导用户配置（确认表之后读这份）

**原则：你来动手，用户只需要回答、发照片、点一次“授权”。** 密钥、密码、验证码**不要让用户发到聊天里**，也不要替用户输入。 能运行代码时，不要让用户去点网页上的黄色按钮、不要让用户复制粘贴代码、不要让用户在网址后面加 `?edit`、不要让用户自己挪文件。这些全由你做，每做完一步用一句大白话告诉用户结果，再问下一件事（一次只问一件）。

先判断你在哪种环境：

| 环境 | 例子 | 怎么交付 |
|---|---|---|
| **A. 能在用户电脑上运行命令** | Claude Code、Cursor、Trae、Qoder、CodeBuddy、Codex、Kimi Code、连接了电脑文件夹的 Claude 桌面版 | 全自动：生成 → 打开预览 → 放照片 → 上线，下面 1–6 步全做 |
| **B. 能运行代码，但在云端** | Claude 网页版、ChatGPT（代码 / Agent）、Kimi Agent、扣子带代码插件的智能体 | 请用户上传项目压缩包和照片，你生成后把 `my-site.zip` 发给用户；上线按第 5 步的 B 做 |
| **C. 只能聊天** | 普通对话模式 | 用 questionnaire.md 末尾“只能聊天”的说明（模板里有「📋 一键粘贴并预览」） |

拿不到模板时（环境 A/B 都需要 `assets/template/` 和 `assets/tools/build_site.py`）：请用户把下载的 `3d-room-website` 压缩包发给你 / 放进工作文件夹，只说一句“把下载的压缩包拖进来就行”。

---

## 1. 生成（不用问用户）

工作文件夹这样放（A 环境放在用户指定的地方，默认桌面上新建“我的网站”）：
```
我的网站/
├── site.json   ← 内容（以后改网站就改它；不上传）
├── 照片/       ← 用户给的原图（可选）
└── my-site/    ← 成品，上线的就是这个文件夹
```
1. 把确认后的内容写成 `site.json`（JSON 格式见 modules.md；不要写 `demo`）。
2. 运行：
   ```
   python3 <skill目录>/assets/tools/build_site.py site.json --out my-site
   ```
   - 出现 ❌：按提示改 `site.json` 再运行，**不要把错误甩给用户**。
   - 报告里的“还空着的照片位置”“找不到文件”留到第 3 步用。
   - 没有 Python：照 SKILL.md「交付方式」手动做同样的事（复制模板、替换 `site-content`、删 `demo`、复制照片）。
3. 自己检查：在无头浏览器或截图工具里打开 `my-site/index.html`（电脑 1440×900、手机 390×844），确认 3D 房间出来了、每个板块能打开、控制台没有报错、**左上角没有黄色的“示例内容 / 编辑中”按钮**（有就说明 `demo` 没删或者打开的是模板）。

## 2. 给用户看

- A：用浏览器打开成品（`build_site.py ... --open`，或 macOS `open my-site/index.html`、Windows `start my-site\index.html`）。
- B：发 2–3 张截图（首页 + 一个板块）。

然后说：
> 🎉 网站生成好了，已经在浏览器里打开（点房间里的东西看看每个板块）。
> 先看看文字和房间有没有要改的？直接说“把 xx 改成 xx”就行。没问题的话，我们来放照片。

用户提修改：改 `site.json` → 重新运行第 1 步 → 刷新 / 重新打开 → 说一句改了什么。

## 3. 放照片（你来放，用户只管发）

按构建报告里“还空着的照片位置”，用用户看得懂的话列出来，然后问：
> 📷 网站上有 3 个地方可以放照片：① 关于我的个人照 ② 作品《夏日便利店》的两张图 ③ 作品《30 秒动画》的封面。
> 照片在电脑哪个文件夹？直接把文件夹拖进来，或者告诉我“桌面上的 作品 文件夹”就行。也可以直接把照片发给我。不想放的说“先不放”。

拿到照片后：
1. A：列出那个文件夹里的图片；B：用户发来的文件在上传目录。能看图就看一眼内容来对应位置，看不了就按文件名对应。
2. 给一张对应表让用户确认（不确定的写“？”并问）：
   > | 位置 | 照片 |
   > |---|---|
   > | 关于我 | IMG_2031.jpg（海边那张） |
   > | 《夏日便利店》 | 封面.png、草图.jpg |
   > 这样放可以吗？
3. 把这些位置在 `site.json` 里直接写成照片的路径（绝对路径，或相对 `site.json` 的路径），重新运行第 1 步。脚本会自动复制、压缩、改名放进 `my-site/media/`，原图不动。
4. 打开 / 截图确认照片显示，再说：
   > ✅ 照片放好了：关于我 1 张、作品 3 张。还空着：《30 秒动画》的封面（之后有了发我就行）。
- 视频：mp4 最好（其他格式提醒一句可能放不了），超过 8MB 提醒会慢；有 ffmpeg 可以帮用户压成 H.264。
- 隐私：照片里有校徽、工牌、电脑屏幕、门牌、别人的脸时提醒一句。
- HEIC（苹果手机照片）：脚本会用 Pillow 或 macOS 的 sips 转成 jpg；都没有就请用户导出成 jpg。

## 4. 问要不要上线

> 🌐 要不要现在放到网上，生成一个能发给朋友的网址？
> - 想先看看效果：我先给你一个临时网址（1 小时内有效，不用注册）；
> - 想长期用：会弹出一个 Netlify 的登录 / 授权页面，你点一下“Authorize”就行，其他我来。
> 也可以先不上线，以后说一声就行。

## 5. 上线（你来跑命令）

需要 Node.js（`node -v` 能出版本号）。没有的话：A 环境问用户能不能帮装（macOS 有 Homebrew 时 `brew install node`），不行就走下面的“拖拽上线”。

**临时网址（不用账号）：**
```
npx -y netlify-cli deploy --dir=my-site --no-build --allow-anonymous --json
```
把输出里的网址发给用户，并说明“1 小时内有效；想保留就说‘保留’”。用户要保留时，按输出里的认领说明办（通常是登录后认领，或运行输出里给出的 `netlify claim ...` 命令）。

**长期网址（A 环境推荐）：**
1. `npx -y netlify-cli login` —— 会在用户的浏览器里打开授权页。只对用户说：“浏览器弹出了 Netlify 的页面，没有账号就用邮箱或 GitHub 注册，然后点 **Authorize**，好了告诉我。”
2. `npx -y netlify-cli deploy --dir=my-site --no-build --prod --site-name <英文名-随机数字> --json`（第一次会新建网站；用户有多个团队时会要求 `--team <slug>`，用 `npx -y netlify-cli teams:list --json` 查）。
3. 记下网站 ID（输出里的 `site_id`），写进 `我的网站/.netlify-site` 之类的文件；以后改完重新部署用 `--site <ID>`，网址不变。
4. 告诉用户：
   > ✅ 上线了：https://xxx.netlify.app 发给朋友就能看。以后想改，直接跟我说，我改完会帮你更新到同一个网址。

**拖拽上线（B 环境，或没有 Node.js / 不能联网）：** 把 `my-site` 打成 `my-site.zip` 发给用户，然后说：
> 下载 my-site.zip 并解压，打开 app.netlify.com/drop，把解压出来的 my-site 文件夹整个拖进网页，几秒钟就有网址了。

国内访客多、想用自己的域名：提一句可以以后再换国内托管（见 deploy.md），不展开。

## 6. （可选）让 AI 分身真的会聊天

上线后问一次：
> 💬 右下角的 AI 分身现在按写好的问答回答。想不想让它接上真正的大模型、什么问题都能聊？需要一个大模型的 API 密钥（比如 DeepSeek，充几块钱能用很久）。不需要的话说“不用”。

用户要：
1. 重新生成时加 `--with-ai`，把 chat 板块的 `endpoint` 写成 `"/api/chat"`，并按 deploy.md 把用户资料整理进 `my-site/knowledge/`（只放愿意公开的）。
2. Vercel：`npx -y vercel login`（同样是浏览器里点一下）→ 在 `my-site` 里 `npx -y vercel --prod --yes`，记下项目名。
3. 密钥由用户自己粘贴，**不要让用户发到聊天里**。帮用户在浏览器里打开两个页面：大模型的密钥页（DeepSeek：platform.deepseek.com/api_keys；其他平台见 deploy.md）和这个 Vercel 项目的 Settings → Environment Variables 页，然后说：
   > 👉 需要你做一步：在 DeepSeek 页面点“创建 API key”并复制；切到 Vercel 页面，Key 填 `LLM_API_KEY`，Value 粘贴刚才的密钥，点 Save。做完回我“好了”。
   （用户更习惯终端的话，也可以给他一条在自己终端里运行的 `npx vercel env add LLM_API_KEY production`，按提示粘贴。）
   用户回“好了”后，你再运行一次 `npx -y vercel --prod --yes`。
4. 打开网站和 AI 分身聊一句，状态显示“在线 · AI 实时回答”就告诉用户成功了；顺便提醒一句：`*.vercel.app` 在国内有时打不开，建议以后绑自己的域名。

## 以后改网站

用户说“把吧台换成书架”“加一段经历”“换张照片”：改 `site.json`（照片同样写路径）→ 重新运行第 1 步 → 打开给用户看 → 上线过的话用同一个网站 ID 重新部署 → 一句话说改了什么、网址不变。
